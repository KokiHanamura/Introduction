# FX 検証のルール（このリポジトリ固有）

検証結果を信用できるものにするための約束。破ると「バックテストでは勝てるのに実弾で負ける」が起きる。

## 正直さ
- 「必ず勝つ」「勝率○%保証」とは書かない・言わない。出せるのは「この条件・この期間で、この期待値だった」まで
- 数字は必ず `python3 -m fxagent ...` の出力から引用する。暗算・推測の数字を成績として書かない
- 合成データ（`synthetic_ohlc` / `demo`）の結果を手法の優位性の根拠にしない

## 検証の作法
- 未来参照禁止: シグナルは足確定時点の情報のみ、エントリーは次の足の始値（`fxagent/backtest.py` の約束を崩さない）
- コストを必ず入れる: スプレッド + スリッページ。コスト 0 の結果は参考値として明記
- サンプル数: 100 トレード未満は「判断不能」と書く。できれば 300 以上、複数の相場環境（トレンド/レンジ/高ボラ）を含める
- 期待値の t 値 < 2 なら「偶然と区別できない」と書く
- 改善（フィルタ追加・パラメータ変更）は前半で見つけて後半（アウトオブサンプル）で確認する。後半で再現しない改善は却下
- 試した条件・パラメータの数を記録する（多いほど偶然の当たりが混ざる）
- 最大 DD・最大連敗はモンテカルロの 95% タイルで語る（バックテストの 1 本の並びは楽観的）
- パラメータは「その周辺でも成績が崩れない」ことを確認する（山の頂上ではなく台地を選ぶ）

## データ
- 時刻は UTC で統一。ブローカーのサーバー時間（GMT+2/+3）のデータは変換してから使う
- `data/raw/` の原本は編集しない
- 実トレード記録（`journal/` の sample/template 以外）はコミットしない（.gitignore 済み）

## 出力
- 分析結果は `reports/<日時>_<名前>/`、人間に見せる結論は当日の `docs/plans/.../` にまとめる
- 結論には「何を検証したか・データ期間・コスト前提・トレード数・OOS の結果・残る不確実性」を必ず書く
